# Model-claim matrix

Validation category: **verification** (scope governance only).

This matrix is deliberately conservative. “Verified” means implemented as
specified; it does not imply agreement with a real building.

## Claim-use rule

A metric may be reported only if it tests a claim in the row above. For
example, zone-temperature RMSE cannot validate occupant behavior, an annual
energy total cannot validate solar position, and passing conservation tests
cannot be described as empirical validation. Dataset additions must update the
relevant row before a report uses them.

Every external dataset used against a claim ID must also have an indexed source
manifest in `data/validation/registry.json`. Listing a suitable dataset in this
matrix expresses intent only; it is not a validation result or evidence that
the dataset was obtained.

All claim rows use the timestamp, alignment, missing-data, uncertainty, metric,
plot, table, and provenance rules in `common_tooling.md`. A domain-specific
deviation must be justified in its registered scientific-result manifest.
